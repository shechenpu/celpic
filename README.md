# CelPic

轻量本地图床：中文界面、SQLite、本地磁盘存储，无需第三方图片托管服务。

> 当前为持续开发的预览版。图片管理、用户创建、存储设置和上传令牌已经可用；WebP 转码、缩略图、EXIF/GPS 清除等尚未完成。不要把“存在自己的服务器”理解为图片自动私密：图片直链不要求登录。

## Windows 本地预览

1. 停止之前的服务：在原终端按 `Ctrl + C`。
2. 双击项目中的 `start-celpic.cmd`。
3. 浏览器打开后台 `http://localhost:1018`；图片只读端口为 `http://localhost:23133`。已经打开的页面按 `Ctrl + F5` 强制刷新。

启动脚本先尝试系统 Node.js，再尝试当前用户的 Codex 内置运行环境。长期使用建议安装 Node.js 24 或更新版本。脚本不会下载软件、修改 PATH 或修改已有账号。

也可以在项目目录执行：

```powershell
node server.js
```

当前应用没有 npm 运行时依赖，不需要执行 `npm install`。Node.js 需提供内置 `node:sqlite`。

默认启动双端口：后台 `1018`、图片 `23133`。如需兼容旧的单端口启动方式，可显式设置 `PORT`：

```powershell
$env:PORT = "8080"
node server.js
```

生产部署也可以设置 `ADMIN_PORT`、`IMAGE_PORT`，或设置 `DUAL_PORTS=1` 强制双端口。显式设置 `PORT` 时优先进入单端口兼容模式，适合旧的本地启动脚本和集成测试。

## 账号与密码确认

所有创建账号的入口都要求填写两次相同的密码：

- 首次初始化管理员。
- 管理员添加普通用户或另一位管理员。
- 管理员开放注册后，由访客自行注册。

页面实时提示不一致，服务端再次校验；缺失确认密码、两次不同、密码过短或过长都不会创建账号。密码长度为 8–128 个字符，用户名为 2–32 个文字、数字、下划线或短横线。登录本身不需要输入确认密码。

管理员可管理所有图片、创建账号和修改设置；普通用户只能列出、统计和删除自己的图片。注册默认关闭。当前用户管理支持列表和创建，禁用、删除用户、密码重置尚未提供。

## 已实现

- 中文后台：上传图片、我的图片、上传令牌；管理员额外拥有图片管理、用户管理、系统设置。上传、个人图库与全站图库是独立页面。
- 浅色/深色模式、手机宽度适配、可上传自定义 Logo；预览弹窗内复制时，右下角提示显示在遮罩上方。
- 加高的居中拖拽上传区，支持选择文件、粘贴、多图上传；下方逐文件显示成功/失败状态。
- 上传结果按卡片从左向右排列，每张图片只有一个链接框；点击直链 / HTML / Markdown 图标，切换到对应格式并复制，无需在上传前选择。每张卡片独立保留选择的格式。
- 我的图片只显示当前账号上传的图片；图片管理仅管理员可见，显示全站图片及上传者。两个图库的统计、搜索、选择和批量操作相互隔离，服务端校验查询与删除范围。
- 两个图库顶部显示统计与搜索；图库卡片从左向右排列，下方仅显示三种格式的复制图标及删除图标，不展开链接文字。点击图片可等比居中预览，预览中可切换并复制链接，也可打开原图。
- JPG、PNG、GIF、WebP 原文件存储；后端检查文件签名而非只信任客户端 MIME。
- 搜索、全选、单张与批量删除（需确认）、批量复制直链 / Markdown / HTML。
- 图片数量、文件总大小、当前选择数。
- 个人上传 Token：只显示一次完整内容、数据库只存摘要、可以撤销，仅可调用上传接口。
- 扁平存储、自定义存储子目录、直链隐藏目录前缀、独立隐藏日期开关。
- Referer 防盗链及允许空 Referer 的开关。
- 首次建站、注册开关、多用户权限隔离。
- SQLite 持久化及旧 JSON 数据自动迁移。
- 登录/注册/上传限流、密码哈希、服务端会话过期、跨站写请求检查和响应安全头。

暂不接受或展示 SVG，包括旧版上传的 SVG。原文件不会被自动删除，但不再通过图片接口公开展示。

## 从上一版升级

**先停止旧版，再启动新版，不要同时运行两版。**

首次启动新版时，如果不存在初始化过的 SQLite 数据库，程序会读取 `data/celpic.json`，在事务中迁移用户、图片索引和设置到 `data/celpic.db`：

- 原来的管理员账号、密码哈希和图片引用保留。
- 图片文件不移动，不要求重新上传。
- 旧 JSON 文件不删除、不覆盖。
- 旧文件损坏时停止迁移，不静默清空数据或重新开放初始化。
- 后续只使用 SQLite；新数据不会再写回旧 JSON。

已有 `/i/随机ID` 直链继续有效。修改链接前缀或日期开关后，已生成的合法旧链接也仍可访问。SVG 除外。

**迁移后不要直接回退启动旧代码**，否则旧程序会读到过期 JSON。回退应恢复完整的同一时间点备份。

## 本地目录与图片直链

默认：

```text
celpic/
├── data/
│   ├── celpic.db        # SQLite 数据库
│   ├── celpic.db-wal    # 运行时可能存在
│   ├── celpic.db-shm    # 运行时可能存在
│   └── celpic.json      # 迁移前的原文件，保留
└── storage/            # 图片原文件
```

容器内所有持久化数据统一放在 `/data`：数据库、设置、操作日志和图片都在这里，其中图片根目录为 `/data/images`。Compose 只需要挂载一个 `/data` 目录，备份和迁移更简单。需要使用其他磁盘根目录时可显式设置 `CELPIC_STORAGE_DIR`；网页只允许在既定根目录之内设置子目录。

在系统设置中填写子目录 `0`、启用扁平化，新图片将写到 `/data/images/0/随机文件名.png`。关闭扁平化则按年/月分层。

存储目录与直链格式是独立设置：

| 隐藏目录前缀 | 隐藏日期 | 生成直链示例 |
| --- | --- | --- |
| 开 | 开 | `/随机文件名.webp` |
| 开 | 关 | `/2026/09/随机文件名.webp` |
| 关 | 开 | `/images/随机文件名.webp` |
| 关 | 关 | `/images/2026/09/随机文件名.webp` |

这里只是链接格式示例，不代表 PNG/JPG 已自动转换为 WebP。存储设置仅影响之后上传的文件，不自动搬移历史图片。

## 发布方式建议

CelPic 是 **Node.js + SQLite + 本地图片文件** 的应用。生产环境必须使用带持久化磁盘的部署方式；只使用临时文件系统的平台重启或重新部署后可能丢失数据库和图片。

### 方案 A：GitHub + Render 一键部署（最省事）

仓库中已提供 `render.yaml` Blueprint。流程如下：

1. 在 GitHub 新建一个空仓库，不要勾选 README、`.gitignore` 或 License。
2. 在本项目目录执行以下命令，把代码推送到 GitHub（把地址替换成你的仓库地址）：

```powershell
git init
git add .
git commit -m "Initial CelPic release"
git branch -M main
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
```

3. 登录 Render，选择 **New > Blueprint**，连接这个 GitHub 仓库并部署。
4. Render 会读取 `render.yaml`，通过 Docker 构建，并挂载 `/data` 持久化数据库和图片。
5. 首次打开 Render 提供的 HTTPS 地址，创建管理员账号。不要把 `data/`、`.env` 或密码提交到 GitHub。

`render.yaml` 默认使用带持久化磁盘的 Starter 方案；如果你的账号或需求不同，可以在 Render 创建时调整套餐和磁盘大小。免费或临时磁盘方案不适合这个项目的正式数据。

> Render 这类平台通常只提供一个外部 HTTP 端口。应用会自动识别平台注入的 `PORT`，切换为单端口模式；后台和图片会共用同一个域名，这是正常的。

### 方案 B：任意 VPS / NAS 的 Docker Compose（最稳妥、推荐长期使用）

适合有自己的服务器、域名和备份策略的情况：

```bash
git clone https://github.com/你的用户名/你的仓库名.git
cd 你的仓库名
cp .env.example .env
docker compose up -d --build
```

默认仅绑定到服务器本机 `127.0.0.1`，然后用 Caddy 或 Nginx 反向代理到 `1018` 和 `23133`。只在确认需要局域网直连时，才在 `.env` 中改为 `BIND_ADDRESS=0.0.0.0`。公网部署必须使用 HTTPS，并将 `COOKIE_SECURE=1`。

更新版本：

```bash
git pull
docker compose up -d --build
```

备份：停止容器后备份整个 `data/` 目录，恢复时也要同时恢复数据库和图片目录。

### 方案 C：直接运行 Node.js

仅推荐本地预览或临时测试。服务器安装 Node.js 24 或更新版本后：

```bash
node server.js
```

它不具备 Docker 的隔离、自动重启和标准化部署能力。

### GitHub Actions 说明

GitHub 只负责保存代码和触发部署，不能替代图片与 SQLite 的持久化存储。推荐把 GitHub 仓库设为 Private，并通过 Render Blueprint 或 VPS Docker Compose 部署；不要把真实数据库、图片、Token 和 `.env` 提交到仓库。
## Docker / NAS

目标是运行在支持 Docker 的 Linux NAS 和 VPS 上。提供 Dockerfile 与 Compose 配置；目前已在本机 Windows Node.js 中验证功能，**尚未逐一实测群晖、飞牛、各 VPS 发行版以及 ARM 设备，也未在当前环境完成 Docker 构建验证**。

```bash
docker compose up -d --build
```

默认将后台 `1018` 和图片 `23133` 映射到主机 `127.0.0.1`，避免首次启动就暴露到公网。Windows Docker Desktop 可通过本机浏览器访问。NAS 需要局域网访问时，可以在项目旁创建 `.env`：

```env
BIND_ADDRESS=0.0.0.0
ADMIN_HOST_PORT=1018
IMAGE_HOST_PORT=23133
COOKIE_SECURE=0
```

然后重建容器。此配置会监听全部网卡，请不要在完成管理员初始化前配置路由器公网转发。

### NAS 挂载权限

Compose 只保留 `./data:/data` 一个绑定挂载，数据库和图片统一落在宿主机的 `data` 目录中。容器以非 root 用户（Node 镜像的 UID/GID 1000）运行。部署前请在 NAS 的权限设置中允许该用户读写这个目录；出现 `EACCES` 时检查目录权限，不要改成 `chmod 777` 或直接改为 root 运行。

将本地已有数据带入 Docker 时，建议先停止服务，把数据库和图片整理到同一个 `data` 目录：数据库文件位于 `data/celpic.db`，图片位于 `data/images/`。旧版本若仍有独立 `storage` 目录，先将其内容复制到 `data/images/`，确认无误后再启动。不要只迁移图片或数据库其中一个。

### 公网与 HTTPS

- 首次建站先在受限网络创建管理员。
- 由 Caddy、Nginx 或 NAS 反向代理提供 HTTPS。
- HTTPS 部署时设置 `COOKIE_SECURE=1`；纯 HTTP 本地预览时保持 `0`。
- 反向代理保留原始 Host，请求体限制应不小于应用的单张限制加 multipart 开销。
- 最好不直接暴露 1018/23133 端口；生产环境建议让后台域名反代到 1018，让图片域名反代到 23133。若代理也在容器中，可配置共享网络访问 `celpic:1018` 和 `celpic:23133`。
- 当前应用不信任客户端 `X-Forwarded-For`，代理后的登录限流按代理地址共享；按真实客户端限流需要在可信反向代理层补充配置。
- 数据文件位于磁盘，不经过第三方存储；但你选择的反向代理/CDN 是否经过第三方是另一项部署选择。

## 后台域名与图片域名分离

CelPic 支持将后台和图片链接分成两个域名。建议例如：

- 后台：`https://admin.example.com`
- 图片：`https://img.example.com`

通过环境变量配置：

```env
ADMIN_ORIGIN=https://admin.example.com
IMAGE_ORIGIN=https://img.example.com
COOKIE_SECURE=1
```

配置 `IMAGE_ORIGIN` 后，上传结果、图库、预览和 Logo 使用的图片地址都会改为图片域名。图片域名在 CelPic 内只允许读取 `/i/图片ID` 或合法旧图片路径，不提供管理后台、登录页、API 和上传接口。后台 Cookie 不设置 Domain，因此只属于后台域名。

反向代理时，两个域名可以指向同一个 CelPic 服务端口；图片域名仍由应用进行只读路径限制。更严格的部署可以在代理层额外限制图片域名只转发图片路径。没有配置这两个变量时，程序保持本地单域名模式，适合 Windows、NAS 本地预览。

历史图片不需要迁移，重新生成的图片链接会使用图片域名；数据库中的图片文件和对象存储配置不会改变。修改环境变量后需要重启 CelPic。

## CelPic 原生上传接口

无需兰空账号、服务或接口。当前未实现兰空、EasyImage、Twikoo 专用兼容层。

在后台“上传令牌”创建 Token，然后调用：

```bash
curl -X POST "https://你的图床域名/api/upload" \
  -H "Authorization: Bearer cp_你的令牌" \
  -F "files=@picture.png"
```

成功返回 HTTP 201：

```json
{
  "images": [{ "id": "随机ID", "original": "picture.png", "url": "/随机ID.png" }],
  "errors": []
}
```

`url` 为本站相对路径。把它拼接到你的图床域名即可得到直链。每次最多 20 张，默认单张 20 MB，请求总大小另有限制；网页会逐张发送。Token 只允许上传，不能访问用户或系统管理接口。

## 本轮安全加固（2026-09-06）

- 登录失败按账号和 IP 分别累计，连续失败 5 次会临时锁定约 15 分钟；成功登录后清除失败记录。
- 会话使用 HttpOnly、SameSite=Strict Cookie，滑动有效期 7 天，并限制同一账号最多保留 5 个活动会话。
- 上传令牌只保存 SHA-256 摘要，权限固定为“仅上传”；可选择永不过期、7/30/90/365 天，到期令牌会被拒绝，列表显示最后使用时间。
- 管理员可通过 `/api/audit-logs` 查看最近 200 条登录、令牌和上传操作日志；日志不记录密码和完整 Token。
- 云存储密钥不会通过后台接口原样返回，页面只显示遮罩；生产环境建议优先使用环境变量覆盖并限制 `.env` 文件权限。
- 上传请求大小会根据后台设置的“单张大小 × 单次数量”动态放宽，同时仍受单张和数量限制约束。

### 备份

可以在停止服务后执行：

```bash
node scripts/backup.js
```

脚本会把整个 `data` 目录复制到 `backups/时间戳/data/`，其中已经包含数据库和 `images` 图片目录。恢复前停止服务并恢复整个 `data` 目录，不要只恢复数据库或只恢复图片。生产环境建议通过系统计划任务定期运行，并将备份目录放到独立磁盘或加密存储中。

`data` 内含 SQLite 数据库、用户密码哈希和云存储配置，备份文件必须按敏感数据保护。

## 安全边界和待完成项

- **图片直链是公开的，不是私密相册链接。** 随机 ID、隐藏路径、防盗链都不等同于登录鉴权或加密。
- **当前保存原图，不清除 EXIF/GPS。** 对位置信息敏感的图片请在上传前自行移除元数据。
- 签名检查不能替代完整图片解码。后续将结合图片处理库补充解码、像素数限制和重新编码。
- WebP 服务端转码、压缩质量设置、缩略图和上传偏好尚未完成。
- 全局 API Token、指定第三方客户端兼容层、相册、回收站、备份恢复界面尚未完成。
- 会话保存在内存中，重启后需要重新登录；账号、Token、设置和图片不会丢失。
- 未提供自动更新、病毒扫描、2FA、安全审计认证或完整公网压力测试，不应宣称可以安全地承载任意不可信用户。

## 备份

最简单的可靠方式：**停止服务后备份整个 `data` 目录**，再启动服务。数据库和图片在同一个目录中，避免备份时漏掉其中一部分。运行时仅复制主数据库文件可能漏掉 WAL 中的数据。备份内包含用户密码哈希和图片，应放在受保护的位置。旧 JSON 包含旧密码哈希，也属于敏感文件。

## 测试

不需要 npm：

```bash
node --test tests/integration.test.js
```

测试使用独立临时目录，不会操作你的账号和图片。覆盖密码确认、管理员/普通用户创建、注册权限、旧数据迁移、上传、路径设置、Token、跨站请求、Referer 和删除等。

可选浏览器回归脚本为 `tests/browser-smoke.cjs`，需要本机可用的 Playwright 与 Chromium。可通过 `PLAYWRIGHT_MODULE` 指向已有 Playwright 安装，通过 `BROWSER_EXECUTABLE` 指定本机 Chrome/Edge 可执行文件，然后运行：

```bash
node tests/browser-smoke.cjs
```

本轮检查记录见 `TESTING.md`。
